# Client-neutral review activity notifications

- **Status:** accepted
- **Date:** 2026-09-27
- **Initiative:** 02-review-notifications
- **Supersedes:** [ADR 2.1](2.1-channels-contract-delivery.md)

A Claude Code channel notification carries review activity into Claude Code, but another MCP client cannot use
that contract without knowing the Claude Code method. MCP logging and resource-update notifications do not carry
review activity into a model's session. The client must decide whether to show an event, send it to the model, or
ignore it.

Decision: when review notifications are enabled, the server declares the experimental
`gerrit/review_activity` capability and sends `notifications/gerrit/review_activity` as an ID-less JSON-RPC
notification. The payload has `content` (the complete llmxml activity block) and `meta` (routing fields). The
server also declares `claude/channel` and sends the same payload through `notifications/claude/channel` for Claude
Code. A client that handles both methods uses one to avoid duplicate activity. Subscription state and polling stay
per-session and do not depend on the client method.

A client that displays notifications without sending them to the model does not provide model-visible activity.
Only clients that deliver review activity to the model should tell the agent to subscribe. A subscription alone
does not establish model delivery. Filters can omit an awaited outcome, so the agent can still use read tools to
confirm its state. No extra Gerrit request or event store is needed for the second method.
