# Default to the read group, and to trail-leaving on own changes only

- **Date:** 2026-07-10
- **Governs:** `internal/config/`, `internal/gerritclient/`, `--groups`, `--own-changes-only`
- **Pinned by:** `internal/config/config_test.go` (`Test_Load_Groups`, `Test_Load_OwnChanges`)

Write capability and trail on other people's changes are the two ways the server can do harm. Zero configuration
enables reads only, and trail-leaving operations stay confined to the account's own changes until the operator lifts
that too. The trade: the agent-as-reviewer use case needs two flags.

## Decision

- **Read-only default.** Zero configuration enables the `read` group only. A write-capable group is always an explicit
  opt-in. `get_server_info` registers outside the groups
  ([ADR 1.4](/design-docs/adr/1.4-server-readiness.md)); it reads no change data and leaves no trail.
- **Own changes only.** `--own-changes-only` defaults to `true`. With `comment` or `transition` enabled,
  trail-leaving operations on changes that the authenticated account does not own are refused until the operator sets
  `--own-changes-only=false`.

## Why

- An agent that leaves unwanted trail on other people's changes is a reputational, externally visible failure. A
  missing capability is an inconvenience that the operator finds locally.
- Flipping a default after publication silently degrades the safety posture of existing deployments.

## Consequences

- The agent-as-reviewer use case, commenting on colleagues' changes, is a primary published use case and does not work
  out of the box: it needs `--own-changes-only=false` as well as a write group. Accepted.

## Rejected

- **`--own-changes-only` off by default** — writes are already opt-in through groups, and least surprise argued for
  off, but defense in depth against an externally visible failure decided for on.

## Revisit if

The agent-as-reviewer case becomes the main deployment, so that the second flag costs most operators. Confidence is
moderate: no usage data exists.

## History

- 2026-11-25 — Read-only default: `get_server_info` registers outside the groups, because a client must check the
  server in every configuration.
