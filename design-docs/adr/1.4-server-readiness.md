# Report server identity and readiness through an always-registered tool

- **Date:** 2026-11-25
- **Governs:** `cmd/go-gerrit-mcp/`, `internal/tools/get-server-info.go`, `get_server_info`
- **Pinned by:** `cmd/go-gerrit-mcp/assemble_internal_test.go` (`Test_Assemble`, `Test_GetServerInfo`)
- **Implementation:** pending — a server with missing, rejected, or unreachable Gerrit credentials still exits at
  startup, and the `get_server_info` result has no `state` (not scheduled)

A client such as the review notifications plugin must learn which server it calls and whether that server can serve
Gerrit before it depends on the server's tools. The server registers `get_server_info` in every configuration, and a
server that cannot reach Gerrit with its credentials starts with that tool only, instead of exiting. The trade: a
misconfigured server stays connected and shows one tool.

## Decision

- **Always registered.** `get_server_info` registers whatever `--groups`, `--include-tools`, and `--exclude-tools`
  select. It reads no change data and leaves no trail, so the posture of
  [ADR 1.2](/design-docs/adr/1.2-safe-by-default-posture.md) holds.
- **Identity for a program.** The result is JSON ([ADR 1.3](/design-docs/adr/1.3-llmxml-output.md)): the server name
  and version, the MCP protocol version of the session, the Gerrit account, and the enabled groups, tools, and project
  allowlist. The version is the release stamp, or else the module version that `go install` recorded.
- **Degraded start.** When the Gerrit credentials are missing, Gerrit rejects them, or Gerrit cannot be reached at
  startup, the server starts with `get_server_info` only. Its result names the state (`not_configured`,
  `credentials_rejected`, `unreachable`, or `ready`) and the reason, and the instructions and stderr name the
  reason too. Invalid flags, unknown groups, unknown tool names, and invalid patterns still fail startup.

## Why

- The user's ruling: "the missconfigured mcp, in the other hand should not provide any tools and report as its auth
  is not complete".
- The user's ruling on version negotiation: "we could make special tool that would provide the information about the
  server and mcp". No mod API exposes the MCP `serverInfo` (Claude Code 2.1.332, 2026-11-25).
- When a stdio server exits, Claude Code shows only "Connection closed" and does not retry for 15 minutes, and a stdio
  server has no authentication status (Claude Code 2.1.332, 2026-11-25). An exit loses the reason.

## Consequences

- A misconfigured server shows as connected in the client's server list. The operator learns the cause from the tool
  result, the instructions, or stderr. Accepted.
- A Gerrit outage at startup leaves the server degraded until the client restarts it. Accepted.
- Every session lists one more tool to the model. Accepted.

## Rejected

- **Exit when the credentials are missing or rejected** — the client shows only "Connection closed" and caches the
  failure for 15 minutes.
- **`get_server_info` in the `read` group** — a tool filter or a write-only group would hide it from the plugin that
  checks the server.
- **The `serverInfo` of the MCP initialize result** — no mod API exposes it.

## Revisit if

Claude Code gives stdio servers an authentication status or exposes `serverInfo` to mods. Confidence is moderate: the
behavior was observed on Claude Code 2.1.332 only.
