# Deliver review notifications through a Claude Code plugin

- **Date:** 2026-07-13
- **Governs:** `plugins/gerrit-review-notifications/`, `internal/tools/get-review-activity.go`,
  `internal/notifications/`
- **Pinned by:** `plugins/gerrit-review-notifications/tests/register.test.ts`,
  `internal/tools/get-review-activity_test.go` (`Test_GetReviewActivity`)

Review activity must reach the model in a session without a fetch by the model. Standard MCP has no push that a model
sees, so a Claude Code plugin does the delivery and the server only reports activity. The trade: delivery works in
Claude Code only.

## Decision

- **Plugin delivers.** The plugin in `plugins/gerrit-review-notifications/` holds the subscriptions of the session,
  calls `get_review_activity` on a timer, and appends the returned activity to the conversation as a note that the
  model reads. When the session is idle, it also submits a short prompt, which starts a turn. One poll makes one
  delivery.
- **Short prompt without review text.** The short prompt holds, for each change, the number and the `summary` that
  the server returns: counts, label names, vote values, and statuses, or the reason a change became unreadable. Text
  that a reviewer wrote reaches the model only in the appended note, which Claude Code marks as a plugin's note and not
  the person's words.
- **Stateless server.** `get_review_activity` reports the activity of each requested change past the `since` and
  `status` values that the caller passes back from the previous result. The server holds no subscription, no timer,
  and no notification capability.
- **Session's own server.** The plugin starts no server. It calls the Gerrit MCP server that the session already runs,
  by the name in the plugin option `server`, so the operator's filter flags and project scope apply to notifications.
- **Visible tool.** `get_review_activity` is in the `read` group and its description tells a model that the plugin
  calls it. Its result is JSON ([ADR 1.3](./1.3-llmxml-output.md)).

## Why

- Delivery by the plugin needs no launch flag and no client capability negotiation: installing the plugin is the whole
  setup.
- The plugin API can add text to a running turn and can start a turn in an idle session, which covers both states of a
  session.
- A stateless tool makes the server the same process for every client, with or without notifications.

## Consequences

- Only Claude Code sessions with the plugin get deliveries. Other clients have the pull tool only. Accepted.
- A model can call `get_review_activity` itself; only the description advises against it. Accepted.
- The poll interval is fixed in the plugin at 60 seconds. Accepted.

## Rejected

- **Claude Code channels contract** (`claude/channel` capability, `notifications/claude/channel` events) — a research
  preview that needs a launch flag in every session and that organization policy can disable.
- **A summary that the plugin parses out of the `review_activity` block** — llmxml has no schema and nothing parses it
  back ([ADR 1.3](./1.3-llmxml-output.md)), and a parsed block puts reviewer-written names into a prompt that starts a
  turn in the person's place.
- **Hiding the tool with `_meta.ui.visibility`** — it hides the tool from the plugin as well as from the model
  (measured on Claude Code 2.1.330, 2026-11-24).
- **A server bundled in the plugin** — a second process whose arguments are fixed in the plugin manifest, so the
  operator's filter flags do not reach it.
- **MCP logging notifications and resource subscriptions** — no documented client shows them to the model.

## Revisit if

MCP gains a standard push that clients show to the model, or the Claude Code plugin API loses the timer, the MCP call,
or one of the two delivery calls. Confidence in the plugin API is moderate: it was verified on Claude Code 2.1.330 and
2.1.331 only.

## History

- 2026-11-25 — Plugin delivers, Stateless server: the channels contract needed a launch flag in every session and
  stayed a research preview, so subscription, polling, and delivery moved from the server to the plugin.
